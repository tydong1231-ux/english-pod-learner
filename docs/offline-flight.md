# 飞行离线版（PWA）

无需 iOS 原生 App、付费开发者账户或每 7 天续签。手机继续使用同一套网页界面。

## 使用流程

1. 在 iPhone 的 Safari 打开已发布的 **HTTPS** 网站，分享 → **添加到主屏幕**。
2. 从主屏幕图标打开 PodFluent，在 Wi-Fi 下进入 **Offline → Add downloads**。
3. 按文件夹、搜索、排序挑选出行想听的 10–30 集，点击 **Download (数量)**。**Select shown** 追加当前筛选结果，跨文件夹保留选择，自动跳过已下载课程。
4. 保持 Offline 页面打开，等下载、音频检查和本地回读校验完成；成功后显示绿色勾选图标，并进入 **Downloaded** 列表。
5. 在 **Downloaded** 展开 **Offline check**，查看集数、离线总时长和存储状态，点击 **Test Offline**。
6. 起飞前开一次飞行模式，关闭并重新打开主屏幕 App，播放一集并拖动进度。
7. 飞机上直接从主屏幕图标打开，进入已下载的课程。回程后可删除下载，不影响云端课程。

首次添加到主屏幕后，请在**主屏幕 App 内**下载课程，不要假定 Safari 标签页与主屏幕 App 共用同一份数据。

**Offline → Install app** 提供 iPhone / iPad 的 Safari 分享菜单操作指引；支持安装提示的浏览器还会显示 **Install on this device**。主屏幕模式显示 **App mode**。指引按需打开，检查面板默认折叠；Library 不再显示下载、安装或离线检查控件，只在已下载课程右侧标注绿色勾选图标。

## 离线内容与检查

### 收听进度

Library、Offline 已下载列表和下载选择列表显示细进度条：Unplayed（未听）、百分比（部分收听）、Played（已听完）。在线、离线播放共用当前站点本地的收听记录；旧版已有离线位置继续使用。未下载的课程也会记录进度，移除音频下载不会删除新版收听记录。旧版未保存过的在线收听历史无法恢复。

进度每 3 秒以及暂停、拖动、切换课程、页面隐藏时保存。听完保留完成状态，重新打开已听完课程从头播放；部分收听课程恢复上次位置。记录按内容来源及课程 ID 隔离，保存在当前浏览器 / PWA 的 localStorage 中，不上传云端。

返回 Library 时定位最近实际播放的一集，并显示“最近播放”和左侧蓝线；保留排序，若旧文件夹或搜索隐藏该集，则恢复到该集所在文件夹并清除搜索。Offline 已下载列表也定位并标记最近播放。没有历史时保留最新未听课程的定位。后续搜索、排序、后台刷新不会反复跳动；进度条和完成状态继续保留。

主屏幕 App 在线冷启动默认进入 Library，已安装旧版的 Offline 启动地址也会迁移；断网冷启动仍进入 Offline。正常点击 Offline 不受影响。

### iPhone 息屏连续播放

播放队列固定为进入播放器时的文件夹与排序。播放器提前读取下一集信息、预取音频，在原生 ended 事件中直接给同一个 audio 元素切源并调用 play，不等待 React 路由或字幕。后续字幕独立加载。支持 Media Session 锁屏播放/暂停、上一集/下一集与定位，并在支持的 Safari 上选择 playback 音频会话。

定时暂停读取实时全局状态：按集数跨切集累计，按时间使用绝对截止时间，并在音频进度和回到前台时补查。用户主动暂停或定时暂停后不会因恢复前台而自动播放；仅失败的自动播放请求会尝试恢复。

真机验收：更新后关闭同站点的旧 Safari 页面和主屏幕 App，再从图标打开。选择至少三集的文件夹与排序，播放第一集接近末尾后锁屏，确认连续跨过两次切集；再验证两集定时停止、30 分钟定时及取消、断网已下载队列，以及返回 Library 的最新播放标记。首次播放仍需用户点击。不要卸载 App 或清除网站数据，以免丢失下载。

网页不能保证被 iOS 强制终止或暂停后的连续播放；桌面浏览器自动测试不等于 iPhone 锁屏实测。真机验收仍需在实际 iOS 版本完成。

- IndexedDB 是应用自己的离线主库，保存完整音频数据、课程信息、逐句/逐词字幕、时长和播放进度。音频单独存表，浏览列表和保存进度不会读取或重写整个音频。
- 下载顺序执行，显示逐集进度；失败的课程保留选中，方便重试。Offline 内切换 Downloaded / Add downloads 保留任务和选择；切换到其他主 tab 会取消剩余任务，已验证成功的课程保留。
- 音频与字幕先完整写入数据库，再回读并比较 SHA-256；校验通过才标记可离线。网络错误、存储不足、不完整音频或无字幕都不会显示成功。
- 音频通过设备的 HTML 音频播放器读取时长；设备不支持的格式会提示失败。单集上限 256 MB，降低手机下载时的内存压力。
- **Test Offline** 不请求云端，重新核对本地音频、字幕及 App shell。校验失败的记录不会继续显示 Ready Offline。
- **Flight Ready ✓** 需要：至少一集完整下载、无未完成记录、启动文件齐全，以及持久存储已授权。
- 播放、句子定位、拖动进度和本地播放队列不依赖网络。进度定期保存，并在暂停、定位、切换课程和页面隐藏时保存；下次打开继续。
- 离线库支持按课程名/文件夹搜索，并显示已听进度；“Continue listening”直接回到最近收听的位置。离线播放入口统一位于 Offline，Library 的绿色勾选图标仅表示当前设备已有完整下载。
- PWA 播放器通过 Service Worker 的应用内音频地址读取数据，支持标准 HTTP Range 分段响应，拖动时不访问云端。桌面环境保留 Blob 地址播放。
- 离线学习时点词会定位音频；AI 释义生成需要联网，不属于飞行离线功能。

## 持久存储

主屏幕 App 启动及下载时会自动调用 `navigator.storage.persist()`。界面显示真实授权结果；未获授权可点 **Enable persistent storage** 重试。

Safari / iOS 17 起支持 Storage API。WebKit 根据是否从主屏幕启动等因素决定授权；持久模式保护该站点免于正常的自动存储驱逐。用户主动清除网站数据或删除相关本地数据仍会删除下载。第一版不提供文件导出或课程包备份。

依据：[WebKit 存储策略](https://webkit.org/blog/14403/updates-to-storage-policy/)。

## 构建与发布

沿用现有网站部署方式：

```sh
npm ci
npm run check
npm run build:web
```

发布目录仍是 `dist-web`。PWA manifest 与 Service Worker 随 web 构建生成，无需新增原生工程。Service Worker 只缓存当前版本的启动 HTML、JS、CSS 和图标，不缓存 Supabase API 响应或音频 HTTP 请求。

应用更新不会强制中断正在播放的旧页面；关闭全部旧页面再打开，可激活已下载的新版本。更新会清理旧 shell 缓存，保留独立的离线课程数据库。

**无需 WhisperX**：手机端只下载电脑端已处理完成的课程。转写入口、模型设置和后台日志继续限定在桌面端。

本地预览生产 PWA：

```sh
npm run build:web
npm run preview -- --config vite.web.config.js --host 127.0.0.1 --port 4173
```

`localhost` / `127.0.0.1` 可以测试 Service Worker。iPhone 上的普通局域网 HTTP 地址不能代替正式 HTTPS 网站测试。

## 验证

- `npm test`：本地回读校验、断网后读取、取消与重试、缺失字幕、损坏音频、空间不足、跨资料库 ID 隔离、删除与进度保存。
- 浏览器测试：先启动上述预览，安装 Chromium 后运行：

```sh
npx playwright install chromium
npm run test:browser
```

测试使用隔离浏览器存储和模拟课程，不访问真实云端数据，覆盖手机布局、批量下载及失败重试、关闭页面后断网启动、离线播放及定位、进度恢复。截图输出到忽略提交的 `artifacts/`。

连续播放回归也包含在 `npm run test:browser`：字幕响应完全挂起时仍自动续播、远程和缓存音源、保持同一个播放器、最后一集停止、一集/两集定时停止、跨集计时与取消、浏览器拒绝自动播放后的点击恢复，以及断网后的下一集自动播放。原生队列单元测试还验证 React 更新之前已调用 play、多次连续切集、过期计时、用户暂停及销毁后不误续播。启动测试覆盖旧安装地址迁移、正常 Offline 导航和新版入口断网冷启动。

浏览器模拟无法确认具体 iPhone 是否授予持久存储，也不能替代真机飞行模式和锁屏播放测试。当前不承诺下载在后台继续执行。

开发环境限制：Windows Playwright WebKit 的 Blob / Service Worker 媒体读取曾失败，不能用该环境的媒体结果代替 Mac WebKit 或 iPhone 真机验收。
